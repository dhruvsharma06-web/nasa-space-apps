## 2. Submission checklist (all required unless marked)

### Team and eligibility
- [ ] Every member is registered for the 2026 challenge, at the **same** Local Event (or the Universal Event), not waitlisted, and listed on the team's Members tab. ([judging guide](https://www.spaceappschallenge.org/resources/judging-awards-guide/))
- [ ] Team size is 1–6 for a Local Event, or 2–6 for the Universal Event. Members can't be added after submission closes. ([judging guide](https://www.spaceappschallenge.org/resources/judging-awards-guide/))
- [ ] The project responds to **one official 2026 challenge** (see §4: **team decision needed**). ([judging guide](https://www.spaceappschallenge.org/resources/judging-awards-guide/), [terms](https://www.spaceappschallenge.org/legal/))

### Project page fields (Team page → Project tab → Edit; save often; use the edit Lock)
- [ ] **Project Name**
- [ ] **High-Level Project Summary**: what we built, how it addresses the challenge, why it matters.
- [ ] **Link to Project Demo**: a **video of 30 seconds or less**, OR **slides (7 or fewer, including title and intro)**. Hosted externally (YouTube, Drive, GitHub…), public, no login. Going over the limit makes us ineligible for Global Judging. Slides must show: team name, member names, the chosen challenge. ([submission guide](https://www.spaceappschallenge.org/resources/project-submission-guide/))
- [ ] **Link to Final Project**: a public link with no login (our GitHub repo and/or the GitHub Pages web build).
- [ ] **Detailed Project Description**: what it does, how it works, benefits, goals, tools/languages/hardware/software.
- [ ] **Use of Super Intelligence (SI)**: say if and how AI tools were used (not shown to judges, but SI markers in the project are).
- [ ] **NASA Data**: the specific NASA data/resources used. **At least one NASA data source or resource is required for a Global Award.**
- [ ] **Space Agency Partner Data and Other References**: list **every** resource (code, text, images, fonts, sounds), even open-source or free ones. This should match `CREDITS.md`.
- [ ] Images on the page: JPG/PNG/GIF up to 10 MB each. Videos and documents can't be uploaded; link them instead.
- [ ] Everything is in **English**. A spoken video may use another language only with English subtitles.

### Content rules
- [ ] **No NASA branding in anything AI-generated**: generated content "may not use, contain, or modify any NASA branding or design elements (such as the NASA logos, flags, or mission identifiers)". ([submission guide](https://www.spaceappschallenge.org/resources/project-submission-guide/))
- [ ] **Mark AI-generated content**: images and videos need a visible watermark; audio, code and data need an acknowledgement in the descriptive text and metadata. ([submission guide](https://www.spaceappschallenge.org/resources/project-submission-guide/))
- [ ] No images, video, audio or likeness of anyone **under 18**. Anyone 18+ who appears must agree that NASA may use their name and likeness. ([submission guide](https://www.spaceappschallenge.org/resources/project-submission-guide/), [terms](https://www.spaceappschallenge.org/legal/))
- [ ] No personal information, no material that promotes commercial products or services, nothing we don't hold the rights to. ([terms](https://www.spaceappschallenge.org/legal/))
- [ ] Our original content is open (OSI licence). **If we don't name a licence, NASA distributes it under Apache 2.0.** Every non-NASA material must be openly licensed, and its licence named in our documentation. ([terms](https://www.spaceappschallenge.org/legal/))
- [ ] No export-controlled information (ITAR/EAR). Our procedures are fictional. ([terms](https://www.spaceappschallenge.org/legal/))

### Links
- [ ] Every link opens in a **private/incognito window** with no login (demo video, slides, repo, web build, APK).
- [ ] Optional: request a FortiGuard web-filter classification for the GitHub Pages site so judges' networks don't block it ([submission guide](https://www.spaceappschallenge.org/resources/project-submission-guide/)). Category: Education. Company name: "N/A".

### Final click (before 21:59 our time)
- [ ] Tick "I have read and understand the project submission requirements … agree to the Participant Terms and Conditions and Privacy Policy."
- [ ] Tick "Confirm All Work is Original" (all external resources listed in References; no copyrighted material without permission).
- [ ] Click **Submit for Judging** and check that the confirmation banner appears. (We can edit and resubmit until the deadline; only the last saved submission is judged.)

## 3. Judging criteria and how our pillars map

Each criterion is scored 1–5 at every judging level. ([judging guide](https://www.spaceappschallenge.org/resources/judging-awards-guide/))

| Criterion | What the guide says a 5 looks like (short) | Our pillars (brief §1) | Evidence to show |
|---|---|---|---|
| **Impact** | Significant problem, wide reach, benefits a large audience | **1 Access** (phone + ~₹1,000 headset instead of a ₹1 lakh+ headset/simulator); **5 Built to scale** | Cost comparison; works in a browser with no install |
| **Creativity** | Original, new approach | **5 Built to scale** (a level = two JSON files → generated 3D scene); **4 Safe AI** | Show the level factory; the coach can't change the score |
| **Validity** | Scientifically sound, feasible, usable, user-friendly | **2 Real training science** (brief → demo → practice → qualify → debrief; deterministic, explainable scoring) | Test counts; first-timer QA results (`docs/QA.md`); honest device matrix |
| **Relevance** | Fully addresses the chosen challenge; **NASA data is a core component, not superficial** | Weakest today, see §4 | Name the challenge and the NASA data used, and show them in the app |
| **Presentation** | Clear, engaging, well-structured story; judged on the demo + the full project | All five; **3 Data for instructors** | 30-second video or 7 slides; README |

Global Award categories (Phase 3, chosen by the executive committee): Best Use of Science, Best Use of Data, Best Use of Technology, Galactic Impact, Best Mission Concept, Most Inspirational, Best Storytelling, Global Connection, Art & Technology, Local Impact. Our best fits: **Best Use of Technology**, **Art & Technology** and **Local Impact** (low-cost phone VR for schools).

Key dates after the hackathon: Global Nominees announced **December 3, 2026**; Global Finalists **December 17, 2026**; Global Winners **January 26, 2027**. ([judging guide](https://www.spaceappschallenge.org/resources/judging-awards-guide/))

## 4. ⚠️ Decisions needed from the team lead (blockers for Relevance)

**4.1 Which challenge do we submit to?** No challenge is named anywhere in the repo. Of the 14 official 2026 challenges, the two closest are:

| Challenge | What it asks for | Fit with ASTRA Academy today |
|---|---|---|
| [Build a Junior Astronaut Mission Trainer](https://www.spaceappschallenge.org/2026/challenges/junior-astronaut-mission-trainer/) | Game/app for **kids aged 7–12** to run a **lunar or Martian outpost**, trading off life support, radiation shielding, power, food and comms delay; **real NASA data encouraged** (DONKI space weather, OSDR, Artemis/Mars data); browser-playable with no download is a plus | Same name and "trainer" theme, but our audience is junior professionals, our setting is a station cabin, and our mechanic is procedures rather than resource trade-offs. L4/L7 (power bus fault) are the closest. |
| [Space Mission Design Game](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/) | Game to **design and manage a complete mission**: spacecraft, instruments, launch, orbit, budget/mass/power/comms trade-offs; up to 4 players | Weaker: we don't do mission design. |

Low-cost ways to raise Relevance if we choose **Junior Astronaut Mission Trainer** (team lead decides; none of this is P4 code):
- Pitch an ages 10+ "junior astronaut" mode with plain language (the challenge mentions older siblings and classrooms too).
- In L4/L7, make the power fault a **trade-off** (shed which load: life support vs comms vs science), and label it.
- Show **one real NASA data point in the app, credited on screen** (for example a real archived DONKI solar-flare alert as the cause of the L4 power fault, embedded and labelled "archived", never presented as live).

**4.2 NASA data (required for a Global Award).** Planned: NASA Blue Marble Earth imagery (TASKS S11, not in the repo yet; today's Earth texture is generated by code). That counts as a NASA resource, but the guide rewards data as a *core component*. See 4.1.

**4.3 Licence.** The repo has no `LICENSE` file, so by default NASA would distribute our original work under Apache 2.0. Proposal: add `LICENSE` (Apache-2.0 or MIT) before submitting. This is a root file with no owner in the brief, so it's the team lead's call.

**4.4 Brand names.** The terms reject "material that promotes commercial services or products". Proposal: say "a ~₹1,000 Cardboard-style phone headset" in the pitch, and name the Irusu Ultra only in the device test matrix.

**4.5 AI disclosure.** We used AI coding assistants and an advisory Gemini coach. Fill in the "Use of SI" field honestly, and watermark any AI-generated image or video (including trailer shots).
